# 画像から 3D モデルを作る機能の計画

キャラ別データセットの素体(正面・横・後ろ・斜め・Aポーズ)や、キャラの画像から、テクスチャ付きの 3D モデルを作る。
骨(リグ)を入れて動かせるところまでを目標にする。2D モデル(`body_rig.py` / `body_layers.py`)と同じく、
素体の仕組みの上に足す。実装はこの計画に沿って、ステップごとに PR を分けて進める。

## 方針

- **入力は素体の絵を使う。** 素体はもう全身5方向(front / side / back / three_quarter / a_pose)をキャラごとに描いていて、
  自動チェック(`body_check.py`)で1人・正しい向きになっている。3D 生成の入力として、正面の A ポーズ・無地の背景が一番よい
  (各モデルの README・自動リグの推奨と同じ)。
- **GPU は利用者自身の Colab で動かす。** 手元の GTX 1070 Ti(8GB・Pascal)では足りない(下の表)。see-through
  (`scripts/see_through_server.py` + `notebooks/see_through_colab.ipynb`)と同じく、Colab のサーバーを cloudflared の
  トンネルで呼び、ジョブ API で待つ。**利用者の画像は公開の Hugging Face Space や外部の 3D 生成サービスに送らない**
  (#127 で決めたこと)。
- **後処理は手元の Blender 4.5 をヘッドレスで使う。** 2D モデルと同じ `admin` 設定の `blender.path` を使う。メッシュの整理・
  大きさと向きの正規化・プレビュー・書き出しは Blender で行う。
- **コンテンツガードは素体と同じ。** 裸の素体からの 3D は、成人の印と18歳以上の年齢があるキャラだけ(`nude_block_reason`)。
  未成年の手がかりがあるキャラはスーツ・水着の素体だけ。参照画像が未成年を示すキャラも作らない。

## 今あるもので使えるもの

| もの | 場所 | 3D で使うところ |
|---|---|---|
| 素体の全身5方向の絵 | `body_base.py`、`<dataset>/body_base(_r18)/<base>_<part>.png` | 生成の入力。多視点を受け付けるモデルなら front / side / back も渡す |
| 自動チェック(WD タグ・頭の数・A ポーズの骨格) | `body_check.py` | 入力の絵の確認。A ポーズの骨格の点はリグの骨の位置の初期値にも使える |
| Colab のサーバーとジョブ API | `scripts/see_through_server.py`、`notebooks/see_through_colab.ipynb` | 同じ形で 3D 生成のサーバーを作る(トンネルは100秒で切れるので、ジョブで待つ) |
| Blender のヘッドレス実行 | `body_rig.py`、`scripts/blender/build_rig.py` | 後処理・リグ・プレビュー・書き出し |
| 動きの定義 | `body_motions.py` | 3D の骨にも同じ動き(wave / walk / jump など)を付ける |
| 揺れ(髪・胸) | `body_physics.py` | 3D では Blender のボーンの揺れ(spring)で同じ考え方を使う(後回し) |
| 素体の年齢・成人の判定 | `routes/lora_dataset.py` の `_age_checks`、`nude_block_reason` | 作れるかの判定をそのまま使う |

## 候補のモデル(2026-10 時点。ステップ 1 で Hunyuan3D-2mv の形だけを使うと決めた)

| 用途 | 候補 | 特徴 | ライセンス・注意 | GPU の目安 |
|---|---|---|---|---|
| 形とテクスチャ | TRELLIS.2(Microsoft) | 1枚の絵から高精細なメッシュと PBR テクスチャ | コードは MIT。描画に使う nvdiffrast などは NVIDIA のライセンス | 試作では A100 でピーク 5.6GB、1体 41〜55 秒。前後の厚みが足りず不採用([試行記録](trials/2026-10-31_model-3d-step1.md)) |
| 形とテクスチャ | Hunyuan3D 2.1(Tencent) | 形(shape)と塗り(paint)の2段。多視点版(2mv)は正面・横・後ろの絵を受け付ける | Tencent Hunyuan Community License(EU・英国・韓国は対象外、月間100万人の上限)。日本の個人利用は範囲内 | 形 約10GB、塗り 約21GB |
| アニメ調のキャラ専用 | CharacterGen(SIGGRAPH'24) | 1枚の絵から、ポーズを A ポーズにそろえた多視点を作ってから 3D にする。アニメ調のデータで学習 | 学習データ(VRM)は再配布不可。重みの条件を要確認 | 要確認 |
| アニメ調のキャラ専用 | StdGEN(CVPR 2025) | 体・服・髪を分けた 3D を作る。2D モデルの「層」と同じ考え方で、着せ替えと相性がよい | コードの公開・ライセンスを要確認 | 要確認 |
| 自動リグ | UniRig(SIGGRAPH 2025) | メッシュから骨の構造と皮膚の重みを予測。.obj / .fbx / .glb / .vrm を読める | コードは MIT と言われている。重み・学習データ(VRoid など)の条件は別に確認 | 8GB 以上 |
| 自動リグ(手元) | Blender の Rigify + 骨の位置合わせ | 人型の骨を A ポーズの骨格の点に合わせて置き、自動の重みを付ける | Blender 同梱(GPL。アプリからは別プロセスで呼ぶだけ) | GPU 不要 |

### 多視点の絵から奥行きを求める方法との比べ

素体の5方向の絵から、写真測量のように奥行きを計算する方法も考えた。結論は、**計算で奥行きを求める方法は主役にせず、
生成モデルの入力(条件)として多視点を使う**。

| 方法 | ライブラリの例 | 素体の絵で使えるか |
|---|---|---|
| 写真測量(SfM + 多視点ステレオ) | COLMAP、Meshroom(AliceVision) | **使えない。** 同じ物を少しずつ違う角度から撮った、細部の一致する写真が数十枚要る。素体の絵は向きごとに別々に描いていて細部が一致せず、角度も90度ずつで重なりが少ない |
| 少ない枚数からの姿勢・奥行きの推定 | DUSt3R / MASt3R、VGGT | **難しい。** カメラの位置が分からない数枚でも動くが、「同じ1つの物」を写していることが前提。絵ごとの食い違いで形がずれる |
| 3D ガウシアンスプラッティング・NeRF | gsplat、nerfstudio | **使えない。** 写真測量と同じく、一致する多数の視点が要る |
| シルエットから形を削り出す(ビジュアルハル) | 自作(numpy)か Blender | **大まかな形なら使える。** 正面・横・後ろのシルエットだけを使うので、細部の食い違いに強い。ただし凹み(脇・股・首)は出ない。生成モデルの結果の自動チェック(ステップ 5)や、身長・体型の確かめに使う |
| 1枚の絵からの奥行きの推定(2.5D) | Depth Anything V2、Marigold | **2.5D なら使える。** 正面から見た奥行きの地図が出る。全周の 3D にはならないが、2D モデルの層に奥行きを付ける(視差で立体的に動かす)のには向く |
| 多視点を条件にした生成 | Hunyuan3D 2mv(正面・横・後ろ)、StdGEN・CharacterGen(内部で多視点を作り直す) | **本命。** 学習済みの人体・服の形の知識で、食い違いを吸収して1つの形にまとめる。素体の多視点は「向きのヒント」として渡す |

外部の有料サービス(Meshy、Tripo、Hunyuan のホスト版の自動リグなど)は品質と手軽さはよいが、利用者の画像を外部に送るので
**使わない**。使うかどうかは利用者が決めることなので、ステップ 0 で確かめる。

## ステップ(1 ステップ = 1 PR を想定)

### ステップ 0: 決めること(決定済み・2026-10-30)

| 項目 | 決めたこと | 計画への影響 |
|---|---|---|
| 何に使うか | **漫画のポーズの参考** | 外で動かす形式(VRM・ゲーム用 FBX)は要らない。代わりに、**ポーズを付けられること**(骨)と、ポーズを付けた絵を描き出せることが要る。書き出しは GLB と Blender のファイル(.blend)にする |
| どの素体から作るか | **裸の素体をもとに、衣服を着せる。裸の素体が無いキャラは水着の素体をもとにする** | 体(裸・水着)の 3D を1つ作り、衣服はその上に重ねる(ステップ 6b)。裸の素体からは、素体と同じく成人のキャラだけ |
| 使い方 | **自分で使うだけ**(配らない・売らない) | Hunyuan3D(日本の個人利用)・TRELLIS.2 の NVIDIA の部品とも、条件の範囲内。VRM の利用条件の欄も要らない |
| GPU | ステップ 1 の結果、**L4 で足りる**(Hunyuan3D-2mv の形だけで 5.7GB) | — |

以下は、決める前に挙げていた項目(記録として残す)。

1. **何に使うか。** 決めたことで、書き出しの形式とリグの要否が変わる。
   - 漫画のコマの構図・ポーズの参考(Blender で回して見る)なら、GLB とプレビューで足りる。
   - VRChat や VTuber など外で動かすなら、VRM と人型の骨が要る。
   - ゲームなら、FBX か GLB と、動きのアニメーションが要る。
2. **書き出す形式。** GLB(既定)、VRM、FBX から選ぶ。
3. **どの素体から作るか。** 候補はスーツ・水着・裸、または衣装(着せ替え)を着せた A ポーズ。
   - 裸からも作るなら、素体と同じ判定で成人のキャラだけにする。
4. **GPU。** Colab の L4(24GB)で足りるかはステップ 1 で確かめる。足りなければ A100(Colab Pro+)にするか、
   塗りを省いて形だけにする。
5. **ライセンスの条件。** 個人で使うだけか、作ったモデルを配る・売るか。後者なら、Hunyuan 系と NVIDIA の部品の条件を
   先に確かめる。

### ステップ 1: 試作して比べる(実施済み・2026-11-01)

結果は [trials/2026-10-31_model-3d-step1.md](trials/2026-10-31_model-3d-step1.md)。
**形は Hunyuan3D-2mv(正面・横・後ろの3方向、形だけ)で作る。** 素体の横の絵とのシルエットの重なりが一番よく、
前後の厚み(胸・お尻)が素体に近い。L4 で1体 2 分半ほど、GPU メモリ 5.7GB。入力の横・後ろの絵は、まっすぐ立った
真横・真後ろであることが前提(歩くポーズなどはそのまま形に写る)。テクスチャは使わない。TRELLIS.2 は細部は一番だが
前後の厚みが足りないので使わない。CharacterGen・StdGEN は未実施で、ステップ 6b の前に試す。

以下は、始める前に立てた内容(記録として残す)。


- 3人の A ポーズで、上の候補(TRELLIS.2 / Hunyuan3D 2.1(1枚・多視点)/ CharacterGen / StdGEN)を Colab で動かす。
  - 体型の違う3人にする: テスト素体(199)、矢野栄子(68)、早瀬 ルミ(223)
  - 全年齢のスーツか水着を使う
- 比べる点:
  - 顔
  - 髪(長い髪・後ろ髪)
  - 手の指
  - 体型が素体どおりか
  - 背中側のテクスチャ
  - 時間
  - VRAM
- 多視点の入力(素体の横・後ろ)が効くかも見る。NovelAI の絵は向きごとに細部が少しずつ違うので、かえって崩れることがある。
- 比べる基準として、正面・横・後ろのシルエットから削り出した大まかな形(ビジュアルハル)も作る。生成モデルの体型が
  素体からずれていないかを、これと重ねて見る。
- 結果を `docs/trials/` に記録し、使うモデルを決める。

### ステップ 2: Colab の 3D 生成サーバー(実装済み)

- `scripts/model3d_server.py` と `notebooks/model3d_colab.ipynb`。see-through と同じ形にした。
  - Hunyuan3D-2mv の形だけ(テクスチャを塗る部品はビルドしない)。L4 で動く。
  - ジョブ API: `POST /jobs`(multipart の front・left・back。front は必須。seed・steps・octree_resolution)→
    `GET /jobs/{id}`(状態)→ `GET /jobs/{id}/result`(形だけの GLB)。
  - 合言葉(Bearer)を全部の呼び出しで確かめる。1度に1体だけ動かす。起動するとすぐにモデルを読み込み始める。
  - cloudflared のクイックトンネルで外に出す(see-through の 8190 と別の 8191 番)。see-through とは別のノートブックにした
    (ライブラリの版が合わないため)。
- アプリ側は `src/python/model3d_remote.py`(`generate(views, out)`)。接続先は see-through と同じく `.env` の
  `MODEL3D_BASE_URL` と `MODEL3D_TOKEN`。
- テスト: `tests/test_model3d_remote.py`(サーバーのモデルを差し替えて、合言葉・仕事の流れ・失敗を確かめる。GPU なしで通る)。

### ステップ 3: バックエンド(生成・保存・判定)(実装済み)

- `src/python/model_3d.py`: 素体の絵を向きに当てて `model3d_remote.generate` に送り、結果を保存する。
  - 送る絵: 素体の「正面」(front)→ front、「側面」(side)→ left、「背面」(back)→ back。正面は必須で、
    横・後ろは描いてあれば送る(計画の a_pose ではなく、ステップ 1 の試作と同じ正面の絵にした)。
  - 横の絵は左向きとして送る。右を向いて描かれた絵は、骨格の点(鼻と耳、取れなければ肩)で見分けて左右を反転する。
- エンドポイント(`routes/lora_dataset.py`)。2D モデルの see-through と同じく、仕事を切り離して画面からポーリングする。
  - `POST /character/{id}/model-3d`: 生成を始める(`base_id` を省くとキャラに当てた素体。`seed` は既定 12345)。
    同じキャラ・素体で動いている間は 409。
  - `GET /character/{id}/model-3d`: 作れる素体ごとに、描いてある向き・作ったファイル・meta・仕事の状態を返す。
    作れる素体は、当てた素体と、このキャラの正面の絵を描いた素体。
  - `GET /character/{id}/model-3d/file?base_id=&name=`: `model.glb`・`meta.json` を返す。
- 保存先: `<dataset>/model_3d(_r18)/<base_id>/`。
  - `model.glb`(生のもの)
  - `meta.json`(モデル・seed・送った向き・横を反転したか・時間)
  - 後処理後の `model_clean.glb` とプレビューは、ステップ 4 で足す。
- 判定: 裸の素体は `_age_checks`(`nude_block_reason`)を通るキャラだけ。通らないキャラには、裸の素体を候補にも出さない。
- テスト: `tests/test_model_3d.py`(向きの見分け・反転・仕事の流れ・裸の素体の判定。GPU なしで通る)。
- 実機(2026-11-01): テスト素体の水着の素体(18)で、PC から Colab(L4)へ送って GLB ができた(生成 190 秒、受け取りまで 321 秒)。
  実際の素体の横の絵 16 枚の向きは、どれも正しく見分けられた(左右反転した絵も右向きと判定)。

### ステップ 4: 後処理(Blender)(実装済み)

- `scripts/blender/clean_model.py`(`model_3d.clean` が手元の Blender 4.5 で画面なしに呼ぶ。設定は 2D モデルと同じ `blender.path`)。
  - 浮いた破片を消す(いちばん大きなかたまりの頂点の数の 1% より小さいかたまり)。
  - 面の数を減らす(Decimate の Collapse。上限は 8万面)。
  - 法線を外向きにそろえ、なめらかに表示する。
  - 大きさを素体の性別と身長の設定に合わせる(女性: ふつう 160cm・低め 150cm・高め 172cm。男性: 172・162・183cm)。
    足の裏を高さ 0、左右・前後の真ん中を原点にする。
  - 向きは Hunyuan3D-2mv の出力のまま(Blender で Z 上・正面 -Y。GLB では Y 上・正面 +Z)。
- 描き出すもの: `model_clean.glb`、正面・横(左向き)・後ろの静止画(`front.png`・`side.png`・`back.png`。
  Workbench の灰色の陰影・透明の背景)、1周 36 コマの `preview.gif`。結果(面の数・消した破片の数・身長)は `meta.json` の `clean`。
- 生成の仕事の最後に続けて整える(状態は `cleaning`)。`POST /character/{id}/model-3d/clean` で、作り直さずに整え直せる。
  Blender が見つからなければ、生成も始めない(422)。
- 実機(2026-11-01): テスト素体の水着の素体(18)の形で、26万面 → 8万面、破片 0、身長 1.60m。Blender の処理は 9 秒ほど。

### ステップ 5: 自動チェック(実装済み)

- `model_3d.check`: 整えた形の静止画(正面・横・後ろ。背景は透明)の影絵を、素体の同じ向きの絵の影絵(`anime_seg` で人を
  切り出す。横の絵を反転して送ったときは反転して比べる)と重ねる。高さをそろえ、左右にずらしていちばん重なる所の IoU を測る。
- 向きごとに 0.65 を下回ったら合わないとして、シードを変えて作り直す(`model_3d.make`)。回数は開発管理者の設定
  `model_3d.check_attempts`(既定 2、最大 4。1回に Colab で 3 分ほど)。いちばん重なりのよい回の形を残し、
  `meta.json` の `check` に向きごとの重なり・理由・作った回数を書く。整え直し(`/model-3d/clean`)でも比べ直す。
- しきい値の根拠(2026-11-01 の実機。テスト素体の水着の素体(18)の形を、ほかの素体の絵とも比べた):
  - 正しい素体の絵: 正面 0.79・横 0.77・後ろ 0.76
  - ほかの 24 体の素体の絵: 平均 0.64〜0.74(立った人の影絵は似るので、別人までは見分けられない)
  - 崩れた絵(2人並び・正面向きの横の絵): 横 0.29・後ろ 0.41
  - なので、このチェックは崩れた形と、合わない入力の絵(真横・真後ろでない)を拾うためのもの。
- 計画にあった WD タグ(髪の色・長さ・体型)は、形だけの灰色の絵では色が無いので使わない。

### ステップ 6: リグと動き(実装済み)

- **骨は A(手元の Blender)で付けると決めた。** 使い道は漫画のポーズの参考なので人型の骨で足り、GPU・Colab が要らない。
  UniRig(B)の利点は揺れもの(髪・服)の骨で、ポーズの参考には要らないので見送った。
- `model_3d.rig` + `scripts/blender/rig_model.py`:
  - 関節: 整えた形の正面の静止画(`front.png`)で骨格推定(`body_rig.detect`。灰色の形の絵でも取れた)をし、正投影のカメラから
    左右 x・高さ z(m)に戻す。奥行き y は、Blender でその (x, z) に正面から光線を通し、形に入る所と出る所の真ん中にする。
  - 骨: 2D モデルと同じ名前と親子(`torso`・`head`・`upper_arm`/`forearm`/`hand`・`thigh`/`shin`/`foot` の `.L`/`.R`。
    `.L` はキャラの左)。重みは Blender の自動(heat)、付かなかった頂点はいちばん近い骨。
  - 動き: `body_motions` の全部をアクションにして GLB に入れる(NLA のトラック)。2D の「絵の面の中の回転」は、
    正面の軸(-Y)のまわりの回転にする。胴の移動(画素)は、素体の絵の高さ 1216 画素を身長とみなして m にする。
  - 書き出すもの: `model_rigged.glb`(骨と動き入り)、`model.blend`(手でポーズを付ける用)、`motion.gif`(指定の動きを斜め前から)。
    結果(関節の 3D の位置・重みの付かなかった頂点の数・動きの一覧)は `meta.json` の `rig`。
- 形を作る仕事の最後に続けて骨を入れる(状態 `rigging`)。整え直し(`/model-3d/clean`)でも入れ直す。
  `POST /character/{id}/model-3d/rig` で、骨だけ入れ直す(確かめの動きを変える)。リクエストの `motion` で動きを選ぶ。
- 実機(2026-11-01): テスト素体の水着の素体(18)で、骨 14 本・動き 7 つ。重みの付かなかった頂点は 0。Blender で 9 秒ほど。
  手を振る・バンザイは崩れずに動いた。「その場で歩く」は 2D 用(脚を横に開閉する)なので 3D では動きが小さい。
  立体のポーズ(座る・歩く・振り向く)はステップ 7 で 3D 用に作る。
- 揺れ(髪・胸)は後回しのまま。
- **手は人形の手に付け替える**(2026-11-01 追加)。Hunyuan3D-2mv は指を作れず、手が指のくっついたひれの形になる
  (`octree_resolution` を上限の 512 にしても同じ)。
  - 作った形の手を、手首の面で平らに切り取り(自動の重みで手・指の骨に付いた所だけ)、切り口をふさぐ。
  - 人形の手: 手のひら(角の丸い箱)と 5 本の指(3 節ずつ、両端の丸い筒)。節ごとに骨(`thumb`/`index`/`middle`/`ring`/
    `little` の `.01`〜`.03`)を入れる(骨は全部で 44 本)。指の骨の X 軸のまわりに回すと、手のひらの側へ曲がる(握る)。
  - 大きさは前腕の長さの 0.74 倍(身長の 9〜12%)。腕を下ろした姿勢に合わせ、手のひらを体の側、親指を前に向ける。
  - 形の割合は、素体の手の絵(手のひら、無ければ手の甲)から `hand_shape.measure` で測る(RTMPose の手の 21 点。
    OpenMMLab、Apache 2.0)。手の長さに対する手のひらの幅・中指の長さと、中指に対するほかの指の長さ。人の手として
    ありえる範囲に収め、曲がった・取れない指と、手の絵が無いキャラは標準の割合。`meta.json` の `rig.hand` に残す。
  - 実機: 手の寄りの絵 5 枚のうち 2 枚で割合が取れ、斜めに縮んだ絵・手の見つからない絵は標準になった。

### ステップ 6b: 衣服を着せる

体(裸か水着)の 3D に、着せ替え(`wardrobe.py`)の衣装を重ねる。次の順に試して、ステップ 1 の結果で決める。

1. **着せた A ポーズの絵から、衣服だけの 3D を作る。** 着せ替えはもう、素体の A ポーズに衣装を着せた絵
   (`body_base/outfits/<base>_a_pose_outfit_<oid>.png`)を描いている。これを 3D にして体との差を衣服とし、体と同じ骨に付ける。
   2D モデルの衣服の層(#121)と同じ考え方。
2. **体・服・髪を分けて作るモデル(StdGEN)を使う。** 衣服が別の部品で出てくるので、着せ替えに一番向く。
   コードの公開とライセンスを確かめてから。
3. **テクスチャだけ着せる。** ぴったりした服(水着・タイツ・薄いシャツ)なら、体の 3D に衣装の絵を投影するだけで足りる。
   スカート・コートのように体から離れる服には使えない。

衣装ごとに作った衣服の 3D は、キャラの 3D に何着でも付け替えられるようにする。

### ステップ 7: ポーズを付けて描き出す(漫画の参考)(実装済み)

- ステップ 6b(衣服)より先に行った(2026-11-01 の利用者の判断。衣服を着せるときは、服と髪にも骨を入れたい)。
- 書き出す形式は、ステップ 6 の GLB(骨と動き入り)と Blender のファイル(.blend)。
- `body_poses.py`: ポーズとカメラの向き。
  - ポーズ: 立つ・歩く・走る・椅子に座る・振り向く・あおむけに寝転ぶ・指さす・バンザイ。骨ごとの回転
    (forward 前へ振る・side 横へ開く・twist ねじる。骨を入れた姿勢からの回転で、親の骨に続けて回る)と、
    左右の手の形(開く・軽く曲げる・握る・指さす)、置く物(椅子)。
  - カメラ: 正面・斜め前・横・後ろ・あおり・俯瞰。遠近のあるカメラ(50mm)で、体の真ん中を向く。あおり・俯瞰は近づけて遠近を強める。
  - 絵の種類: 灰色の陰影(Workbench、上からの照明、床あり)と線画風(EEVEE + Freestyle の輪郭・境目・折れ目の線、白い背景)。
  - ポーズはコードで増やす。DB で増やすのは、画面(ステップ 8)を作るときに必要なら足す。
- `scripts/blender/pose_render.py`: model.blend にポーズを当て、体のいちばん低い所を床に合わせ、椅子を置き、カメラごとに
  832×1216 の絵を描く。`model_3d.render_pose` が呼び、`poses/<ポーズ>_<カメラ>_<種類>.png` に置く(骨を入れ直す・
  整え直すと消す)。1 ポーズ・1 カメラで 3〜5 秒。
- `POST /character/{id}/model-3d/pose`(pose・cameras・style)。GET `.../model-3d` に、素体ごとのポーズの絵の一覧と、
  ポーズ・カメラ・絵の種類の名前(`pose_options`)を返す。絵は `.../model-3d/file?name=poses/...` で取る。
- あわせて直したこと(ステップ 6 の骨入れ):
  - 素体の正面の絵は足をそろえて立つので、作った形は左右の足首・足がくっついていて、歩く・走るで足の間が膜のように伸びた。
    重みを付けたあと、膝から下を左右の足首の真ん中の面で切り離し、反対側の脚の重みを外す。
  - 新しく作った Blender の world にはノードが無い、model.blend は透明の背景のまま保存されている、Freestyle は
    ビューレイヤーの側でも有効にして線の設定を作る、が要った。Blender の中のエラーが終了コードに出るよう
    `--python-exit-code 1` を付ける。
- 描き出した絵を、漫画のコマを描くときの i2i の元絵として使えるかは、別に試す(NovelAI には ControlNet が無いので、
  i2i の強さで構図を寄せる)。

## 気を付けること

- **向きごとの絵の食い違い:** 素体の横・後ろは、正面と細部が違うことがある。多視点の入力は、横・後ろがまっすぐ立った真横・真後ろのときだけ使う(ステップ 5 で確かめる)。
- **髪・スカート・指:** どのモデルも崩れやすい。後処理と自動チェックで拾えない崩れは、画面で作り直せるようにする。
- **背中側のテクスチャ:** 1枚の絵からだと推測になる。後ろの素体の絵を塗りの参考に使えるかを、ステップ 1 で見る。
- **時間とお金:** 1体に数分かかる見込み(see-through は1枚 約450秒)。Colab の利用枠を使うので、一括生成は付けず1体ずつにする。
- **成人向けのデータ:** 裸の素体の絵も Colab(利用者自身のアカウント)には送るが、公開の場所には送らない。
  作ったモデルのファイルは `_r18` のフォルダに分ける(素体と同じ)。
- **ライセンス:** ステップ 1 で使ったものは次のとおり(自分で使うだけなら、どれも範囲内)。
  - TRELLIS.2 のコード: MIT。
  - DINOv3(TRELLIS.2 が画像の特徴を読むのに使う): Meta の独自のライセンス。Hugging Face で利用者が申請・同意し、
    Colab のシークレット `HF_TOKEN` でログインする。トークンはノートブックに書かない。
  - 背景消し: 公式の briaai/RMBG-2.0 は申請制で非商用(CC BY-NC 4.0)なので使わず、`ZhengPeng7/BiRefNet`(MIT)に差し替える。
