# 試行記録: ギャラリーの拡大表示の範囲を高解像度にする(切り出して img2img・AI 拡大)

- 日付: 2026-10-15
- ブランチ: `feat/gallery-region-redraw`
- 状態: **採用**(AI 拡大 → img2img の描き直しと、AI 拡大だけの2通りを入れた)

## 目的

ギャラリーの全画面で拡大して見ている範囲を、高い解像度にしたい(ユーザーの要望)。元の画像は 1MP 前後なので、
拡大すると線がぼやける。

## 方法

1. 全画面の拡大表示で、いま画面に見えている範囲を、元の画像のピクセルで求める(倍率と移動量から計算する)。
2. その範囲を切り出し、縦横比を保って大きくする。
3. 描き直し: NovelAI の img2img で、弱めの強さで描き直す。
   - 大きさは 1MP 以内・64 の倍数(4倍まで)、ステップは 28 まで(Opus なら Anlas 0)
   - プロンプト・シードは元の画像の設定(メタデータ)から取る。絵全体のための構図・人数のタグ(`full body`・`2girls` など)は外し、
     切り出した範囲を判定モデル(リバースプロンプトと同じもの)で読んだタグを足す
   - キャラごとのプロンプトは、位置を指定して描いた画像なら、範囲の中にいるキャラだけを、範囲の中の位置に直して残す
4. 結果はギャラリーに新しい画像として残し、元の画像のキーを記録する(「元の画像を開く」で戻れる)。元の画像は変えない。

## 試し1: 単純な拡大(LANCZOS)→ img2img

832×1216 の画像の顔のあたり 400×400 を、1024×1024 にして描き直した。

| 強さ | 結果 |
|---|---|
| 0.25 | 顔・色・表情は元のまま。線と塗りがきれいになる |
| 0.35 | 同じく元のまま。0.25 より少し描き直しが強い |
| 0.5 | 髪の流れや頬の赤みが変わり始める |

元の粗さ(拡大でぼやけた線)は、弱い強さでは残った。

## 試し2: AI 拡大(超解像)を元にする

ユーザーの提案で、描画系の AI で粗い部分を補う方法を調べた。アニメ絵向けの超解像モデルのうち、この PC の
onnxruntime(判定モデルと同じ)でそのまま動くものとして、CDC のアニメ向けモデル
([deepghs/cdc_anime_onnx](https://huggingface.co/deepghs/cdc_anime_onnx)、MIT ライセンス、約160MB、4倍)を使った。
Real-ESRGAN のアニメ向けモデルは、公式には PyTorch の重みだけで、ONNX にするには PyTorch が要るので見送った。

同じ範囲で比べた(くっきり度: 輪郭を取った画像の分散。元とのずれ: 128×128 に縮めた明るさの差の平均)。

| 方法 | くっきり度 | 元とのずれ |
|---|---|---|
| 単純な拡大だけ | 449 | 1.78(基準) |
| AI 拡大だけ | 1228 | 2.05 |
| 単純な拡大 → img2img 0.25 / 0.35 | 460 / 487 | 5.44 / 6.76 |
| **AI 拡大 → img2img 0.25 / 0.35** | **1090 / 1085** | **4.79 / 5.74** |

AI 拡大を元にすると、描き直しの結果は**くっきりして、しかも元に近くなった**。描き直しの元には AI 拡大を使う。

### AI 拡大のモデルの注意(実機で確かめた)

- 入力の縦横は 16 の倍数でないと動かない。端の画素で広げてから通し、結果から切り落とす。
- 出力の形は `(1, 3, 4, 高さ, 4, 幅)` と書かれているが、そのまま `(3, 4×高さ, 4×幅)` に並べ直したものが正しい
  (形の名前どおりに並べ替えると、元の絵と大きくずれた)。
- CPU で 400×400 に 15〜25 秒。0.26MP を超える範囲は、先に縮めてから拡大する。

## 使い方(画面)

ギャラリーで画像を開き、全画面にして拡大すると、下に方法の選択と「この範囲を高解像度に」が出る。

| 方法 | 中身 | 時間の目安 | Anlas |
|---|---|---|---|
| 描き直し 控えめ / ふつう / 強め | AI 拡大 → img2img(強さ 0.25 / 0.35 / 0.5) | 1分ほど | Opus なら 0 |
| AI拡大だけ | この PC で4倍(4MP まで) | 30秒ほど | 使わない |

ほとんど拡大していない範囲(解像度が 1.25 倍も上がらない)は断る。

## 費用

描き直しも含めて、Anlas の消費は 0 だった(試しの前後で同じ)。

## 残っている課題

- AI 拡大は CPU で動くので、広い範囲は時間がかかる(先に縮めているので、元の細部は少し失われる)。
- 範囲の中の人物の人数や構図は、判定モデルの読み取りに頼る。読み違えると、描き直しで違う絵になることがある
  (強さを控えめにすると、ずれは小さい)。
