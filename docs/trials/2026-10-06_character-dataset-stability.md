# 試行記録: キャラ別データセットの安定生成の設定比較

- 日付: 2026-10-05 〜 2026-10-06
- ブランチ: `feat/manga-v2`
- 状態: **完了**(結果をキャラ別データセットの既定値に反映済み)

## 目的

キャラ別データセット(`/character-dataset`)で、服装・ポーズ・表情・場所を変えても
同じキャラとして出る設定を見つける。あわせて、参照画像との類似度で引き直す機能(ガチャ対策)が
実用になるかを確かめる。

## 対象

- キャラ: 九条 ゆら(`characters.id = 83`, トリガーワード `kujo_yura`)
- 参照画像: 最初にゆらを生成した1枚(`outputs/manga/refs/char83_*.png`)
- キャラシート
  - 容姿: `1girl, solo, brown hair, long hair, loosely hair, two side up, pink scrunchie, hair scrunchie, yellow eyes, narrowed eyes, sanpaku, detailed eyes, beautiful eyes`
  - 画風: `ai-generated, authentic, best quality, masterpiece, flat color`
  - ネガティブ: `short hair, black hair, blonde hair, blue eyes, red eyes`
  - 基準シード: `3257661879`(全枚で固定)

## 共通の生成条件

- モデル `nai-diffusion-4-5-full`、832×1216、steps 23、scale 5.0、`k_euler_ancestral` / `karras`
- ネガティブ = 既定(`lowres, worst quality, ...`) + キャラシートのネガティブ + 全年齢向けの `SAFE_NEGATIVE`
- NovelAI へは1枚ずつリクエスト(ただし後述の「実施上の問題」を参照)

## 試行1: 最初の4枚(改善前)

改善前のキャラ別データセット機能そのままで4枚生成した。

- 参照: キャラ＋画風・強さ 1.0(当時の固定値)
- バリエーション: 構図の軸なし。組み合わせは完全ランダム

| # | 服装 / ポーズ / 表情 / 場所 | 色の類似度 |
|---|---|---|
| 0001 | 浴衣 / 本を読む / 半目 / 街 | 0.09 |
| 0002 | コート+マフラー / 手を振る / にやり / 街 | 0.11 |
| 0003 | 制服+カーディガン / 手を振る / にやり / 街 | 0.80 |
| 0004 | コート+マフラー / 手を振る / 笑顔 / 教室 | 0.11 |

分かったこと:

- 4枚とも同じキャラに見えた(茶髪ロングのツーサイドアップ、ピンクのシュシュ、黄色い三白眼)
- 4枚とも上半身・正面の、ほぼ同じ構図になった
- ポーズが偏った(4枚中3枚が「手を振る」)
- 0004 のコートの下に参照画像のピンクのリボンが出た(参照画像の服装が混ざる)
- 色の類似度は主に服の色で決まる。同じゆらでも制服は 0.80、浴衣やコートは 0.1 前後

これを受けて次の3点を実装した。

1. 構図の軸(`FRAMINGS`: full body / cowboy shot / portrait / close-up / from side など)
2. 組み合わせの均等化(`balanced_combos()`: 各軸の値が均等に出るように選ぶ)
3. 参照する範囲の選択(キャラのみ / キャラ＋画風)

## 試行2: 類似度の採点方法の比較(NovelAI は使わない)

試行1の4枚と、別キャラ(`outputs/training_data_v4_5/cahrunna/`、茶髪・茶色の目)の2枚を
参照画像と比べた。VLM は Ollama の `qwen2.5vl:7b`(GTX 1070 Ti)。VLM は1枚につき2回採点した。

| 画像 | 色 | VLM(2回) |
|---|---|---|
| ゆら 0001(浴衣) | 0.09 | 0.85 / 0.7 |
| ゆら 0002(コート) | 0.11 | 1.0 / 1.0 |
| ゆら 0003(制服) | 0.80 | 0.9 / 1.0 |
| ゆら 0004(コート) | 0.11 | 1.0 / 1.0 |
| 別キャラ(顔アップ) | 0.04 | 0.0 / 0.3 |
| 別キャラ(上半身) | 0.33 | 0.5 / 0.5 |

- 色の類似度は服装を変えるデータセットでは使えない(同じキャラでも服の色で 0.1〜0.8 に散る)
- VLM は別キャラを低めに付けるが、別キャラの上半身にも 0.5 を付けた
- VLM は1回あたり 8〜30 秒かかった

## 試行3: 参照のかけ方の比較(4設定 × 4プロンプト)

構図・服装・ポーズ・表情・場所をすべて散らした固定の4プロンプトを、設定ごとに1枚ずつ生成した。
シードは全枚で基準シード固定。

| # | 構図 | 服装 | ポーズ | 表情 | 場所 |
|---|---|---|---|---|---|
| 1 | full body | yukata | walking | smile | shrine |
| 2 | cowboy shot | hoodie, jeans | arms crossed | expressionless | cafe |
| 3 | portrait, close-up | sundress | hand on own cheek | pout | park |
| 4 | from side | school uniform, blazer | sitting on chair | smirk | library |

| 設定 | 参照の範囲 | 強さ | VLM(2回 × 4枚) | Anlas/枚(Opus / Opus以外) |
|---|---|---|---|---|
| A | キャラ＋画風 | 1.0 | 1.0/1.0, 0.9/0.5, 0.9/0.5, 1.0/0.7 | 5 / 22 |
| B | キャラのみ | 1.0 | 1.0/1.0, 1.0/0.6, 1.0/1.0, 1.0/1.0 | 5 / 22 |
| C | キャラのみ | 0.7 | 1.0/0.9, 0.9/1.0, 1.0/0.9, 1.0/0.9 | 5 / 22 |
| D | 参照なし | — | 0.9/1.0, 0.9/1.0, 1.0/1.0, 0.7/1.0 | 0 / 17 |

Anlas は SDK の `GenerateImageParams.calculate_anlas()` による見積もり。

目視の結果(4×4 の一覧で比較):

- **見た目の一致**: 4設定とも、髪型・シュシュ・黄色い三白眼は保たれた。D は目がやや橙寄り
- **設定間の差**: A は色が参照画像に近い(フラットで淡い)。B と C はほぼ見分けがつかない。
  D は服の細部が参照画像に引っぱられない(例: 4 のリボンが赤のストライプになった)
- **構図の軸**: full body / cowboy shot / close-up はタグどおりに描き分けられた。
  `from side` はどの設定でも無視され、正面寄りになった
- **シードの影響**: 同じプロンプトなら、4設定でほぼ同じ構図・色になった
  (例: 浴衣は全設定でピンク)。構図と色を主に決めているのは基準シード

## 結論

1. 見た目の安定は **基準シード + 容姿タグ** でほぼ決まる。参照画像の上乗せ効果は小さい
2. 参照画像を使うなら **キャラのみ・強さ 0.7**。キャラ＋画風は画風まで元画像に寄せる
3. 類似度での引き直しは、今の採点方法では **実用にならない**
   - 色: 服装を変えると同じキャラでも点が下がる
   - VLM: 16枚すべてに 0.5〜1.0 を付け、同じ画像でも 0.5 と 0.9 のように採点がぶれる
4. 構図の軸と組み合わせの均等化で、構図とポーズの偏りは解消した

## 既定値に反映した内容

| 項目 | 変更前 | 変更後 | 場所 |
|---|---|---|---|
| 参照画像を使う | オン | オフ | `CharacterDatasetRequest.use_reference`、画面の初期値 |
| 参照の範囲 | キャラ＋画風 | キャラのみ | `CharacterDatasetRequest.reference_type`、画面の初期値 |
| 参照の強さ | 1.0 | 0.7 | `CharacterDatasetRequest.reference_strength`、画面の初期値 |
| 最大試行回数 | 1 | 1(画面に「通常は1を推奨」と表示) | 画面 |
| 横顔の構図 | `from side` | `from side, profile` | `character_sheet.FRAMINGS` |

画面の初期値は localStorage に保存した値があればそちらが優先されるため、以前に設定を変えた
ブラウザでは自動では切り替わらない。

横顔は、利用者の知見で `from side` に `profile` を組み合わせると効きやすい(本試行では未検証)。

## 実施上の問題

- 試行3の前半(2026-10-06 00:56〜01:05 ごろ)、実験スクリプトが2つ同時に動き、
  NovelAI へのリクエストが並列になった。中断したと判断した最初のプロセスが実際には動き続けていたため。
  Git Bash の `ps` では Windows のプロセスが見えず、見落とした
  - 同じ番号の画像を両方のプロセスが生成して上書きした可能性があり、数枚分の Anlas が余分にかかった可能性がある
  - 再発防止: 再開の前に PowerShell の `Get-CimInstance Win32_Process` で実行中のプロセスを確かめる
- 2つのプロセスが同時に Ollama を使ったため、VLM の採点がタイムアウトや空応答で止まった。
  `vlm_similarity()` に、空応答とタイムアウトのときに最大3回まで採点し直す処理を足した
- `tests/_run_subscription_check.py` は NovelAI の API 変更で HTTP 400 になり、Anlas 残高を確認できなかった
