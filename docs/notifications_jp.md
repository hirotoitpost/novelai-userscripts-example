# 処理終了のブラウザ通知

物語ページのシーン分割・タグ付け・コマ生成などの長い処理が終わると、ブラウザの通知で知らせます。

- **ページからの通知** — ページを開いている間に終わった処理を通知します(15秒以上かかったもの、または別のタブ・アプリを見ている間に終わったもの)。
- **Web Push** — サーバーからブラウザのプッシュサービス経由で通知します。スマホの画面を消していても、ブラウザを閉じていても届きます。

物語ページ上部の「🔔 処理が終わったら通知する」を押して許可すると、両方が有効になります。「テスト通知」で届くか確認できます。

## 使える条件

ブラウザの通知は **安全なコンテキスト(HTTPS か localhost)** でしか使えません。

| 開き方 | 使えるか |
|---|---|
| PC で `http://localhost:5173` | そのまま使える |
| スマホ(Android の Chrome)で `http://192.168.x.x:5173` | 下の設定をすれば使える |
| iPhone | HTTPS で開き、ホーム画面に追加したアプリから開いたときだけ(iOS 16.4 以降) |

## Android の Chrome で LAN の IP から使う

1. Chrome のアドレス欄に `chrome://flags/#unsafely-treat-insecure-origin-as-secure` を入力して開く
2. 欄にフロントエンドとバックエンドの両方を、カンマ区切りで入力する
   (例: `http://192.168.0.10:5173,http://192.168.0.10:8000`。物語ページの通知欄にも、開いている URL に合わせた値が表示されます)
3. 右のプルダウンを **Enabled** にし、「Relaunch」で Chrome を再起動する
4. 物語ページを開き直し、「🔔 処理が終わったら通知する」を押して許可する

PC の IP が変わったら、登録し直してから通知をオンにし直してください。

### 「自動でブロックされました」になったとき

Chrome は通知の許可ダイアログを出さずに自動でブロックすることがあります(「リクエストの表示方法」が
「不要なリクエストを閉じる」のときや、ダイアログを何度か閉じたとき)。その場合は手で許可します。

1. Chrome の ⋮ →「設定」→「サイトの設定」→「通知」
2. 「許可しないサイト」にある `http://<PCのIP>:5173` の ⋮ →「許可」
3. 物語ページに戻り、「画面を消していても届くようにする」→「テスト通知」

## 仕組み

- VAPID の鍵は初回に `data/vapid_private.pem` として作られます(`data/` は git 管理外)。この鍵を消すと、各ブラウザはページを開いたときに自動で購読し直します。
- 購読しているブラウザは DB の `push_subscriptions` テーブルに保存されます。失効した購読(404/410)は送信時に削除されます。
- 通知の中身は暗号化されてプッシュサービス(Chrome なら Google の FCM)に渡ります。載るのは物語の番号・処理の種類・結果のメッセージだけです。
- ページからの通知とサーバーからの通知は同じ tag(`nai-job-<物語ID>`)を使うので、両方届いても1件にまとまります。

設定(`.env`):

- `PUSH_CONTACT` — プッシュサービスに伝える連絡先(既定: `mailto:noreply@example.com`)
- `PUSH_MIN_SECONDS` — これより早く終わった処理はサーバーから通知しない(既定: 15)
